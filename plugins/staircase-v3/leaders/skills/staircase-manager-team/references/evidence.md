# Evidence and honesty

The rules that keep an answer true when the data is partial. They apply to every skill and every answer about a customer.

| Rule | How |
|---|---|
| Every claim carries its source | A stored field by name ("Risk level, stored"), a report (what it counted), or an evidence id. Mark interpretation as interpretation |
| Quotes are verbatim | Quote only text returned by `staircase_fetch_evidence`. Summaries from `staircase_list_communications`, `call_summary`, search snippets and event quotes are not quotable as anyone's words: a summary can carry a fact "per the summary" with its evidence id, never a quote. Name a speaker only when the fetched message shows the sender, and only when that sender is a customer-side participant (type Stakeholder), not our staff or a partner. In a transcript, name a speaker only when the tag matches a Stakeholder on that meeting row, and add "per the transcript". Text quoted inside a message (a forwarded or replied-to block) is not that sender's words: mark it "author not shown". Event quotes carry no speaker |
| Participants are senders | A communication's `participants` are its senders; on a recorded meeting, the people on the call (it can include invitees who never spoke: say "on the invite" when unsure). Recipients (To, Cc) appear in no tool. Never say someone was "on the thread" or "copied" from participants; "took part" means wrote or attended |
| Stored fields win on account-level claims | Per `single_account_analysis`: overall risk, churn, renewal, expansion and sentiment come from stored fields; threads give the specifics. When recent threads contradict a stored field, show both with their dates: stored flags can lag a conversation |
| Null is not a negative | A blank AI field means not assessed. Zero threads means not visible to this user (thread access is per user). A missing expansion row means not analyzed. An insight at zero can be how the tenant is set up. A null boolean means "not set" (filter it with NotEqual true, not Equal false). Write "not assessed" or "not visible", never "no issue" |
| Base rate before absence | Before flagging a missing field row by row ("no QBR", "no decision-maker touch"), COUNT how many accounts in scope carry it. Near zero: report one setup gap, not N flags. A flag true on more than 80 percent of the scope, or on none, does not separate accounts: drop it and name it. The guard needs 5 or more rows; on fewer, keep the flag and say the base rate was not checked |
| Coverage beside sparse counts | Risk level, expansion readiness and business-review dates are sparse. Print the count with its coverage: "9 renewals at risk 4 or 5, of 14 with a risk level (48 renewing)". A count over a sparse field is a floor of the assessed set |
| Floors from search | Semantic search is ranked, not exhaustive, and cannot prove absence. A count from it prints "at least N, from search" |
| Signals are not intent | A churn notification is something said, not an outcome: check `customer.status` and the renewal synopsis. Signals decide what to read; read before calling an account leaving, safe or at risk |
| Freshness before trends | Before any ticket claim or topic trend, compare the org-wide MAX `customer.ticket.last_opened` with the org-wide MAX `customer.email.customer_last_sent`: two scalars with no scope filter, since a quiet book's own latest ticket can sit weeks back. More than 7 days apart means the ticket feed has likely stopped: print "ticket data as of <date>" and drop tickets from comparisons across the stop (`data-rules.md` rule 24). A blank MAX means tickets are not connected. A ticket sync flag can read healthy while ingestion has stopped |
| Open-thread counts are not "you owe" | `customer.email.customer_open_threads` likely counts threads where the customer wrote last. Direction is inferred from code (one table unread) and not confirmed live: read the thread's last message before saying who owes a reply |
| Count accounts, not rows | Event and opportunity reports return one row per event or offering. Count distinct accounts. Never sum free text (budget, opportunity value) |
| Dates | Write day and month ("renews 6 Dec"). Compute day counts in a filter or a script, not in prose |
| Say what you could not see | Threads read out of `total_count`, blank fields, fields this tenant lacks, a window that cut off history, mailboxes not connected |
| A surprising zero or full table is a question | Before reporting 0 rows or every row, check the option id, the operator and the window. Wrong argument values return empty results with no error |
